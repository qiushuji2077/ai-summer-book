## 先看哪个文件

《门后的光_网站配套文稿.md》包含网站上的完整正文、金句、停顿提问、补充解释和六处互动中的全部情境与反馈。可以直接用 Markdown 编辑器打开、批注和改写。

阅读网站的目录、翻阅、字号、底色、进度和音乐属于界面功能。正文内容单独保存，后续修改文案不必重新设计页面。

## 文稿格式怎样对应画面

每章开头有一行 `<!-- chapter: {...} -->`。其中 `id` 是章节标识，`part` 是篇号，`label` 是“第一章”这样的显示名称，`title` 是标题，`subtitle` 是标题下的导语。大标题改变时，同时修改这里的 `title` 与下方的 `# 标题`。

| 文稿写法 | 网页呈现 |
| --- | --- |
| 普通段落，段落之间空一行 | 舒展的正文 |
| `## 小节标题` | 章内小节，并进入右侧小节目录 |
| `**重要词句**` | 正文中的加粗强调 |
| `> 一句值得停留的话` | 带群青侧线的金句段落 |
| `:::lead` 到下一个 `:::` | 章首的宋体引入段 |
| `:::aside 提示名称` 到下一个 `:::` | 浅底补充解释 |
| `:::pause 提示名称` 到下一个 `:::` | 上下留白的思考停顿 |
| `:::details 补充标题` 到下一个 `:::` | 可展开的补充说明或来源 |
| `[来源名称](https://...)` | 可主动打开的来源链接 |

普通 Markdown 编辑器可能把 `:::` 显示为文字，网站会把它识别成不同的阅读段落。每个块都要保留一行独立的 `:::` 作为结尾，暂不嵌套使用这些块。

例如：

```markdown
## 一个问题怎样打开

这里写正文。一个段落讲清一个意思，留出换气的位置。

> 这里放一段值得停下来读的核心表达。

:::pause 想一想
如果换一个条件，你的判断会不会改变？
:::
```

## 六处互动文案也在同一份文件

互动由 `:::interactive 类型名` 开始。第一行是互动标题，第二部分是说明，后面的每个 `### 情境名称` 对应一个按钮或任务步骤，其下是点击后出现的文字。

| 位置 | 类型名 | 体验 |
| --- | --- | --- |
| 第四章 | prediction | 更换前文，比较可能的续写 |
| 第五章 | context | 增加背景条件，比较安排变化 |
| 第六章 | agent | 逐步经历读取、查找、检查、交还 |
| 第八章 | counterexample | 比较能够与不能推翻判断的例子 |
| 第十三章 | evidence | 区分事实性主张、观点与想象 |
| 第十五章 | permission | 判断行动是否处在既有授权内 |

这些互动使用预设材料说明概念，不调用真实模型。可以直接改写现有情境和解释；如果新增互动类型或改变操作方式，需要同步调整网站行为。

## 以后怎样继续写

你可以直接在配套文稿中修改，把改好的文件交回来，并说明需要更新哪些章节。我会保留当前的网站视觉与阅读功能，将修改后的正文同步进去。

如果自行维护网站代码，正文母本在 `dist/book.md`。修改后运行 `python scripts/sync-content.py` 同步离线阅读数据，再发布新版本。仅修改下载到电脑里的 Markdown，不会自动改动线上网站。

当前每章大约适合三至四分钟的基础阅读。读者可以通过目录自由进入，保留本机续读位置，调整字号、纸白或夜读底色，并主动开启或暂停轻音乐。没有跨设备同步。

序章沿用原资料中“写给你”、六条主线和六个阅读约定的核心内容，做了适合网页阅读的整理。原资料末尾的同类图书比较属于编写背景，本版没有把未经独立核实的比较判断写进儿童正文。
