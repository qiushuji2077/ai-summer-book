# 门后的光文稿编辑说明

这份说明帮助你把后续写作接到已经建立的网站中。当前以《在打开这本书之前》里的六条主线为依据，形成序章与六篇十八章。当前正文为 v0.3 儿童阅读修订稿，尚未作为正式出版定稿。

## 先看哪个文件

`dist/book.md`（网站下载名为《门后的光_网站配套文稿.md》）包含网站上的完整正文、金句、停顿提问、补充解释和六处互动中的全部情境与反馈。可以直接用 Markdown 编辑器打开、批注和改写。

阅读网站的目录、翻阅、字号、底色、进度和音乐属于界面功能。正文内容单独保存，后续修改文案不必重新设计页面。

## 文稿格式怎样对应画面

每章开头有一行 `<!-- chapter: {...} -->`。其中 `id` 是章节标识，`part` 是篇号，`label` 是“第一章”这样的显示名称，`title` 是标题，`subtitle` 是标题下的导语。大标题改变时，同时修改这里的 `title` 与下方的 `# 标题`。

| 文稿写法 | 网页呈现 |
| --- | --- |
| 普通段落，段落之间空一行 | 舒展的正文 |
| `## 小节标题` | 章内小节，并进入右侧小节目录 |
| `**重要词句**` | 正文中的加粗强调 |
| `> 一句值得停留的话` | 带群青侧线的金句段落 |
| `:::lead` 到下一个 `:::` | 章首的宋体引入段 |
| `:::aside 提示名称` 到下一个 `:::` | 浅底补充解释 |
| `:::pause 提示名称` 到下一个 `:::` | 上下留白的思考停顿 |
| `:::details 补充标题` 到下一个 `:::` | 可展开的补充说明或来源 |
| `[来源名称](https://...)` | 可主动打开的来源链接 |

普通 Markdown 编辑器可能把 `:::` 显示为文字，网站会把它识别成不同的阅读段落。每个块都要保留一行独立的 `:::` 作为结尾，暂不嵌套使用这些块。

例如：

```markdown
## 一个问题怎样打开

这里写正文。一个段落讲清一个意思，留出换气的位置。

> 这里放一段值得停下来读的核心表达。

:::pause 想一想
如果换一个条件，你的判断会不会改变？
:::
```

## 六处互动文案也在同一份文件

互动由 `:::interactive 类型名` 开始。第一行是互动标题，第二部分是说明，后面的每个 `### 情境名称` 对应一个按钮或任务步骤，其下是点击后出现的文字。

| 位置 | 类型名 | 体验 |
| --- | --- | --- |
| 第四章 | prediction | 更换前文，比较可能的续写 |
| 第五章 | context | 增加背景条件，比较安排变化 |
| 第六章 | agent | 逐步经历读取、查找、检查、交还 |
| 第八章 | counterexample | 比较能够与不能推翻判断的例子 |
| 第十三章 | evidence | 区分事实性主张、观点与想象 |
| 第十五章 | permission | 判断行动是否处在既有授权内 |

这些互动使用预设材料说明概念，不调用真实模型。可以直接改写现有情境和解释；如果新增互动类型或改变操作方式，需要同步调整网站行为。

## 以后怎样继续写

你可以直接在配套文稿中修改，把改好的文件交回来，并说明需要更新哪些章节。我会保留当前的网站视觉与阅读功能，将修改后的正文同步进去。

如果自行维护网站代码，正文母本在 `dist/book.md`。修改后运行 `python scripts/sync-content.py` 同时同步内置阅读数据与完整静态版，再发布新版本。仅修改下载到电脑里的 Markdown，不会自动改动线上网站。

阅读时间按当前文稿估算，仅作参考；操作图解和停下来思考不计入。读者可以通过目录自由进入，保留本机续读位置，调整字号、纸白或夜读底色，并主动开启或暂停轻音乐。没有跨设备同步。

## 内容与素材说明

序章沿用原资料中“写给你”、六条主线和六个阅读约定的核心内容，做了适合网页阅读的整理。原资料末尾的同类图书比较属于编写背景，本版没有把未经独立核实的比较判断写进儿童正文。

技术内容采用稳定概念，并加入 Project Astra、Genie、AlphaFold 与智能体工程的具名来源。相关链接于 2026 年 9 月 12 日复核；正式出版前仍应复核技术状态、产品要求、事实表述和儿童阅读难度。

封面为本项目生成的插画。轻音乐《窗边》为本项目合成的约 138 秒无歌词器乐旋律，未使用外部歌曲或采样，读者点击后开始循环。


## v0.2 的结构注释

v0.2 版的 `dist/book.md` 与提供的重写稿一致；v0.3 已在此基础上润色儿童语言。为区分“先呈现的材料”和“点击后显示的解释”，六处互动的每个情境增加了明确的结构注释。网页不会根据“已知”“安排”等中文关键词切割段落。

```markdown
:::interactive context
同一个问题，换几张材料

比较每次究竟多知道了什么。

### 只有任务
<!-- option: {"schemaVersion":1} -->
已知：周六要观察植物。

<!-- response -->
这里写按需展开的解释。
:::
```

`<!-- response -->` 之前是材料，之后是解释；两部分都来自母本。没有单独材料的类型可以把分隔注释放在解释之前。六种 `interactive` 类型名和 `preface`、`ch01` 至 `ch18` 的标识保持不变。

反例选项中的 `rectangles` 保存宽、高，单位为厘米。四图共用同一 SVG 画布与厘米比例；修改尺寸后请核对周长、面积和正文。`evidence` 与 `permission` 的 `judgement` 是对应判断按钮的零起始序号；它只影响反馈提示，不评分、不锁住正文。

`<!-- visual: {...} -->` 标记插图位置。图解结构集中在 `reading-modules.js`，标记缺失时保留正文。对照、提示与信笺会将原段落移动到图解内，不维护第二套正文。改写这些段落开头时，应同时检查对应布局是否仍正确接入。

普通 GFM 表格现已支持，表头与行名保留语义，窄屏只在表格区域内横向滚动。不要用空格排表格，也不要把公式做成不可选择的文字图片。

每次修改后运行 `npm run build` 和 `npm test`。预览时优先检查改到的情境、对应静态解释、手机布局和下一章入口。完整静态版 `read.html` 可直接阅读或打印，不要求读者先做完互动。


## v0.3 儿童语言与动画解说

全书由一个代理完整润色，再交另一个代理独立审查；具体问题退回润色者修改，复审后由主代理接入。审查记录保存在 `docs/editorial-v0.3/`。这套流程检查语言与概念，并不代替真实儿童试读。

七段动画的唯一文字母本是 `content/animation-scripts.json`。每段保留 `id`、`visual` 和 `chapter`，每一步有 `title`、`caption`、`alt`；`caption` 同时用于可见字幕和可选语音，`alt` 是该步画面的可访问说明。改变画面、数据或步骤时，应同步核对三项，尤其不能提前在描述中透露尚未揭示的答案。

运行构建后，`dist/animation-script.md` 是可单独编辑批注的解说稿副本；回装时请把改动写回 JSON 母本。语音使用设备提供的中文朗读功能，当前不包含录制音轨，也不保证每台设备都有中文声音。

新增播放器的每一步都生成完整静态分镜。不开动画、开启减少动态、关闭脚本和打印时，解释仍可阅读。减少动态不会禁止听解说，但只读当前一幅，不自动换图。

第十一章的三层提示按第一层标签到 V11 标记之间的段落接入，不再依赖最后一句的固定措辞。改完正文后请检查三层都能展开，提示后的解释没有丢失。
