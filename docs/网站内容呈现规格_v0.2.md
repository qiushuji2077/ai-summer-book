## 一、这轮修改，先把什么做好

**让读者在读到概念以前，先看见一件事怎样发生；读完以后，能用自己的话解释一个具体的变化。**

《门后的光》的框架值得保留：小学与初中之间的读者、六篇十八章、六条主线、六个阅读约定，以及“写给你”的陪伴语气。本轮完整重写已在另一份文件落实。网站要承担的任务，是帮助这份文字被理解，给比较、观察与判断一个可操作的位置。

本轮优先处理的困难有三类：概念之间跳得快；生活案例刚出现就转入道理；互动中“看到了结果”与“自己作出了判断”的区别不够突出。这些判断依据上传文稿及其互动文字，未声称完成现网界面的视觉审计。

## 二、为什么初稿读起来仍有门槛

### 1. 陌生词出现得比经验快

第四章接连引入 token、参数、训练、推理、注意力，第六章又进入工具、Agent、任务循环与 Harness。对成人来说，每个解释都不长；对刚接触这些概念的孩子来说，要同时记住几个关系，仍然费力。

**已落实的改写：**第四章先让读者续写，再介绍训练；单独比较训练时与回答时。第五章始终使用工作桌与资料柜的关系。第六章围绕同一张植物观察清单展开，Harness 放入选读栏。

**网站动作：**核心名词第一次出现时，提供一句就地释义；更深一层的内容可展开。不要在一句话上叠三个提示气泡，更不要把理解主线所必需的解释全部折叠。

### 2. 比喻有亲和力，映射还需要走完整

“接话机”“工作桌”“工作室”能拉近距离，但读者还需要知道各部分分别对应什么，以及比喻在哪里停止适用。只增加拟人小机器人，会进一步模糊模型、产品、工具与人的边界。

**已落实的改写：**第四章标题调整为“一句话，怎样接着长出来”，保留接话入口，明确它无法代表完整模型能力；工作桌对应当前上下文，资料柜对应可能的外部存储，找回资料后还要检查时效。

**网站动作：**把这些关系画清楚。所有机器“思考”的演示标为“教学示意”或“工作步骤示意”，不要包装成模型内心的实况录像。

### 3. 案例需要经过一次“出问题”，才能带出判断

纸桥、树叶、校园地图都是好材料。初稿有些地方只举到名称，随后进入原则，读者没有充分经历为什么需要这些原则。

**已落实的改写：**纸桥出现滑落，记录出现条件不一致；校园地图遇到“近”与“适合”的不同需求；溪桥旧照片只能支持“已经存在”，无法支持“建于该年”。这些转折把需要判断的地方显出来。

**网站动作：**把转折前后的证据放到同一视野，支持回看。不要让读者先背查证清单，再去寻找它的用途。

### 4. 学习建议容易连续变成劝告

如果很多段落都以“你要”“你应当”结束，即使内容正确，孩子仍容易觉得被提醒得太密。

**已落实的改写：**第十章处理第一判断，第十一章处理帮助的大小，第十二章完成一次探究。允许直接查词、看完整解释和求助，不把每次使用工具都变成训练仪式。

**网站动作：**无强制填写、无倒计时、无积分。允许“我先继续读”，也允许直接查看解释。留下自主权，避免把一本书变成另一套练习系统。

### 5. 正确性提醒需要与创造机会保持平衡

技术限制值得讲清，同时要让读者看见 AI 可以怎样实实在在地帮忙：整理记录、指出遗漏、比较表达、探索方案、改善作品。

**已落实的改写：**增加这些具体合作步骤；第三章用可追溯的酶研究案例补足科学应用；第十七章把作品做成“真实读者试用后再修改”的过程。

**网站动作：**每项风险提醒尽量接到一个可采取的动作。例如“没核实”后面提供“看看资料支持了哪句话”，不只弹出警告。

## 三、全书怎样读起来像一条路

### 3.1 保留两条能回来的案例线

**纸桥线：**第一章看能力与结果，第八章看条件与证据，第十一章看怎样获得合适的提示。再次出现时，读者会发现自己比上次多了一种判断工具。

**校园观察与作品线：**第五、六章准备观察，第九章理解地图与现场，第十二章完成一页有依据的记录，第十七章将内容交给真实读者。

其余案例各有职责：桌面遮挡讲可用信息；语言双场景讲语境；溪桥档案讲引用支持范围；郊游方案讲授权。

不要让同一案例承包全部十八章。必要的回返能建立联系，适度换场让阅读保持新鲜。

### 3.2 一章的基本节奏

推荐顺序是：**遇见情境 → 产生一个疑问 → 获得解释或操作 → 看见变化 → 带走一个可迁移的理解。**

它是编辑判断的参考，不要求所有章节套同一版式。科学案例可以采用“问题与研究步骤”，语文章可以采用“两段文字面对面”，收束章应回到连续散文与信笺。

章节首屏保留篇名、标题、一句具体副标题与引入，不叠加大幅图片、背景视频和功能面板。主问题可以紧接引入出现，正文第一屏就应进入实际内容。

### 3.3 三层阅读，但只有一条主线

| 层级 | 放什么 | 怎么呈现 |
| --- | --- | --- |
| 连续阅读 | 理解本章不可缺的情境、解释、核心结论 | 默认完整可读，正文不逐字打出 |
| 帮助理解 | 比较图、步骤演示、少量主动操作 | 与相关段落相邻，随时可跳过 |
| 继续探索 | 专业术语、原始来源、研究边界 | 可展开，打开不丢失原阅读位置 |

核心边界不能藏进第三层。例如“这是示例数据”“研究预测尚须验证”“此处没有实际发送”必须紧贴相关内容默认显示。

每章可先显示“本章会弄明白什么”，暂不把结论全部放在标题下剧透。阅读时长只作参考，不用进度条判断读者已经理解。

## 五、九处优先呈现的具体规格

### 5.1 ch02 / V02：看得见的部分，究竟增加了什么

**问题：**多给了一张图片，为何还可能无法确认？

初始状态先展示文字：“桌上有几支笔？”读者可直接进入下一步，无须回答。

第一张桌面图：三支完整可见的笔；笔袋遮住第四个细长物件的大部分，露出部分不能可靠确定其种类。图旁文字：“完整可见：3 支；遮挡处：暂时无法确认。”

按钮：“看看被遮住的地方”。操作后并置第二张图，笔袋移开，显示第四支笔。此时文字：“在本示意图中，现在能确认 4 支。”保留“回到遮挡状态”。

**图中文字原文：**“只有文字”“增加照片”“补充可见信息”。

**机制限制：**第四支笔是作者预先绘制的内容；浏览器没有识别图片。不要展示识别置信度、扫描光束或虚假加载。

**无动画版本：**两张静态图纵向排列，分别标明遮挡与补充信息；屏幕阅读器直接读出上述文字。仅用 CSS 隐藏露出物体时，不能把被遮挡答案提前放进当前状态的替代文本中。

**验收：**读者能说清“照片也可能看不全”，而非只记住“多模态有三个输入按钮”。

### 5.2 ch04 / prediction：让前文的变化成为焦点

沿用正文三种情境与原类型名 `prediction`。第一屏只显示前文与“先在心里接一句”；点击“看看一种接法”，显示预设续写与理由。

切换情境时高亮前文中改变的部分，其他内容保持位置稳定。禁止使用“模型正在思考”，禁止把任意设定的 85%、10%、5% 画成概率条。

不做逐 token 的闪烁表演。一次显示短语即可；可在边注解释真正 token 的切分依具体系统而变。

**反馈原文来源：**配套正文 `ch04 → :::interactive prediction`。其中“日常的放学路”“童话里的云朵”“已经落下的雨”是情境，不是答题选项。

**无脚本版本：**按三组前文、接法、解释顺序完整列出。

**验收：**读者能解释为何“糖果”在童话前文中更容易说通，也能说明这并非现实证据。

### 5.3 ch04 / V04：分清两个时刻

这一处应独立于接话演示，但不新开页面。

两条水平流程在桌面端上下排列，手机端全部纵向阅读：

训练时：`训练材料 → 预测与比较 → 调整参数 → 形成模型能力`。

回答时：`现有模型 ＋ 当前材料 → 生成回答`。

在第二条放入一张条件纸：“纸桥跨度是 15 厘米”。纸只进入“当前材料”，随后出现“这次回答可以利用这个条件”。不要把纸飞进参数区域。

可以加一个切换：“只看关系 / 看一次过程”。默认静态，过程播放由读者主动触发，最后停在完整关系图。任何动画结束后都保留文字。

**图下固定说明：**“这是区分两个时刻的教学示意，没有展示完整训练流程。一次对话使用了新条件，不等于该信息被永久训练进模型。”

**验收：**读者能将“提前练本领”与“现在使用材料”对应到两条流程。

### 5.4 ch05 / context：材料改变，方案也应跟着改变

保留一个始终不变的问题：“周六的植物观察，应该怎样安排？”

上方展示“目前提供的材料”；下方展示“这一份材料允许我们先做到哪里”。三种情境按顺序排列，但允许来回切换。

| 状态 | 先显示的材料 | 主动查看后显示 |
| --- | --- | --- |
| 1 | 周六要观察植物 | 先询问地点、时间、组织要求 |
| 2 | 校园内、30 分钟、老师带领 | 5 分钟说明＋15 分钟观察＋10 分钟交流；仍为草稿 |
| 3 | 加入雨天限制 | 时间暂不变，地点和方式重新确认 |

切换时只标记新增条件与受影响的部分。不要整页重新打字、整张卡片跳动。

资料柜可作为旁边的静态补图：`已保存的旧安排 → 找回 → 核对日期与条件 → 放到当前桌面`。旧日期要有“可能过时”文字，不仅改变颜色。

**验收：**读者能解释为什么补一条“雨天限制”会改变原方案，且不会把“保存过”说成“这次一定用到了”。

### 5.5 ch06 / agent：重点放在改变计划的那一刻

沿用正文四步，做成带有工作结果的记录，不画成一个机器人连续冒出四个气泡。

每步显示“当前材料 / 做了什么 / 得到什么 / 下一步”，其中第一次只显示已知任务。读者点击“看工具返回的材料”后，才出现 A、B 可对应、C 存疑。

到 C 存疑时增加一个判断：“继续补一个名称，还是保留待确认？”两种选择都说明后果，不羞辱、不计分。把 C 明确留在待确认栏，再进入交还。

**结束画面：**“已整理：A、B；待确认：C 的名称；已保留要求：不采摘；当前结果：交老师检查的草稿。”

**固定提醒：**“步骤由本书预设，未调用搜索或真实智能体。”

**无脚本版本：**四条工作记录全部展开；分支说明直接紧跟第三条。

**验收：**读者指出 C 的查询结果改变了原计划，也能说明停止仍可以是合理的任务结果。

### 5.6 ch08 / counterexample：让图承担真正的解释

这处值得做精确图解。两组长方形必须使用同一厘米比例，不得为了画面好看把每个形状拉成同样大小。

首组保留 1×9 与 4×4；次组保留 2×3 与 4×5。正方形属于长方形的说明贴近首组，不另开术语弹窗。

操作顺序：先看尺寸与形状 → 选择“赞同 / 不赞同 / 暂时拿不准” → “比较周长” → “比较面积” → 查看结论。允许直接查看解释，不强制做选择。

描边表示周长，内部方格表示面积。除了视觉区别，同时显示完整算式、数值与单位。不能只用两种颜色代替两种量。

| 尺寸 | 周长 | 面积 |
| --- | --- | --- |
| 1×9 厘米 | 20 厘米 | 9 平方厘米 |
| 4×4 厘米 | 16 厘米 | 16 平方厘米 |
| 2×3 厘米 | 10 厘米 | 6 平方厘米 |
| 4×5 厘米 | 18 厘米 | 20 平方厘米 |

第一组结论强调“推翻一定”；第二组强调“一次符合不能证明全部”。结束补一个迁移问题：“能不能反过来说周长越大，面积一定越小？”

**无动画版本：**四个同尺度图与计算表，结论直接相邻。打印时必须完整显示。

**验收：**读者能在另一组尺寸中判断反例，不能仅凭“选中了正确按钮”判定学会。

### 5.7 ch11 / V11：三层提示，给读者自己停下的机会

初始画面显示情境：“我看到折法 B 有几次托住更多橡皮，不知道能不能写它永远更结实。”

第一层：“两种折法的纸桥，两端间距一样吗？”

第二层：“把条件一致的尝试单独列出来。你能确认的结果，适用于这些尝试中的哪一部分？”

第三层：“可以先写‘在这几次、这些条件下……’，随后交代没有控制好的地方。”

默认只显示三个层级的题名，不直接泄露各层文字。按钮用“看第一点提示”“再给我一点帮助”“看看表达起点”；始终提供“直接看全部提示”。不设置强制等待。

已经展开的层级保留，不覆盖，读者能看到帮助怎样增加。可提供“收起提示”，但正文继续阅读永远可用。

**固定说明：**“这里不会生成结论，请使用你实际得到的记录。”

**验收：**读者知道第二层提供的是比较方法，第三层提供的是表达起点，结果仍须来自记录。

### 5.8 ch13 / evidence：从分类，再走到支持范围

保留事实、审美判断、故事想象三种情境，让读者先说“我要找资料 / 我要听理由 / 这是故事”，再读反馈。三类不设高低排名。

同章增加静态或轻交互的查证台：左边放“建于 1998 年”的主张，右边放练习用旧照片说明。点击“原文支持了哪一步”，高亮“1998 年已经存在”，随后解释缺少建造年份。

不能把虚构的《溪桥小记》做成可跳往网上搜索的真实书目。资料封面、照片和页码都统一标“虚构查证练习”。若制作旧照片外观，不得使用生成图冒充真实档案。

**无图版本：**一段档案说明与正文支持范围表已足够。图片只是让对读更直观。

**验收：**读者能说清“出处存在”与“足够支持结论”的差别。

### 5.9 ch15 / permission：先看到授权，再看到行动

授权句必须固定在每个情境上方：“老师只授权整理三个郊游备选方案。”

行为按钮是“比较公开资料”“发出家长通知”“填写信息并付款”。选择后先问“可以继续 / 需要确认 / 暂时拿不准”，再显示原因。界面不使用真实“发送”“支付”操作控件。

结果区同时呈现三件事：是否在当前授权内、原因、此时可以怎样交还。不要只用绿色对号或红色叉号。

“查不到资料”和“没有授权”分开处理：前者保留信息缺口，后者交还决定权。它们不能统一被叫作“系统失败”。

**验收：**读者能指出同一个动作的许可与当前授权有关，不能把“会做”直接等同于“可以做”。

## 六、插图与动画，怎样用得克制又有价值

### 6.1 先问这张图解释什么

| 目的 | 适合的媒介 | 本书对应 |
| --- | --- | --- |
| 比较同时存在的差异 | 并置文字、静态图、表格 | 两个现场、两条路线、引用与原文 |
| 说明空间与数量关系 | 精确方格图、标注图 | 长方形、叶片测量 |
| 说明材料或状态的变化 | 读者主动推进的前后对照 | 遮挡、上下文、提示增加 |
| 说明工作次序与反馈 | 分步记录、分支流程 | 智能体与授权 |
| 留下情绪与余韵 | 连续文字、轻插画、留白 | 序章与终章 |

动效应当显出一个变量怎样影响下一步。整页淡入、飘落粒子、悬浮卡片和逐字打字，会增加运动，却不一定增加理解。

### 6.2 一套适合本书的图像语言

建议沿用已有纸白、群青与安静的阅读气质，以手边物件和可检查的图解为主。本文未取得原网站样式文件，具体色值与字体需回到实际页面核对，不能把建议值叫作原站精确色板。

优先画纸张、书本、尺子、笔袋、叶片和记录纸。少用人形机器人、发光大脑、数据流和通用图标。物件本身就是解释材料，不需要再为每段加一个象征图标。

科学结构可以使用简化教学示意；若采用真实结构图，必须给出对象、来源及使用许可。示意分子不可套用真实结构编号。

中文、算式、数字与图注保留为网页文字或可编辑矢量文本，避免烘焙进生成图片。无文字的情境插画可以后续另行生成，但本轮没有交付生成插画。

### 6.3 四张值得精修的图稿任务书

**图一：训练与回答。** 构图以上下两条流程为主。上条有训练材料、比较与参数调整，下条有现有模型、当前材料与回答。纸桥“15 厘米”只进入下条。画面关键词：清晰、留白、关系准确。拒绝大脑拟人图与发光神经装饰。完整文字见 5.3。

**图二：工作桌与资料柜。** 一张工作台表示当前可用材料，侧边文件柜表示可能保存的记录。柜门到桌面之间有“找回并核对”的过程；旧日期与新日期并列。模型不坐在桌前，不画成一个拥有人的记忆的角色。

**图三：长方形反例。** 同一网格比例，1×9 与 4×4 并列；宽屏可横排，手机上下排。边界与内部方格分别可强调，尺寸、单位始终可读。优先使用原生 HTML/CSS 或 SVG 绘制，禁止由图像模型生成算式与格数。

**图四：叶片长度怎么量。** 正视叶片，一端标“叶片基部”，一端标“叶尖”，叶柄以浅描边单独标出“不计入本次长度”。标尺与叶片处在同一平面的关系写在图注。旁边用一幅斜拍小示意说明拍摄角度会影响判断。不得让图暗示必须采摘叶片。

### 6.4 动态与静态的共同要求

默认静态可读，点按后才启动步骤变化。核心文字不隐藏到视频或动画结束以后。提供“上一步”“下一步”“看全部”“重新开始”，不是每个模块都必须同时放四个按钮；依据操作需要取舍。

转场可先以 160—240 毫秒的轻变化试排，数值是设计起点，需实测；不得把时间节拍当作儿童必须跟上的速度。页面离开视口后暂停不必要运动，切章时取消未完成的动画任务。

尊重 `prefers-reduced-motion`，并提供“减少动态”设置。系统已要求减少动态时，不应通过站内默认设置重新强制打开。打印与脚本失败时保留等价的文字、图注和结论。

W3C 对自动运动内容、交互触发动画及可读性有相关要求，见文末资料说明。这里的节奏与样式建议属于本书的设计选择，不声称已经通过可用性研究。

## 七、正文排版、音乐与动线

### 7.1 先保证连续阅读

宽屏正文建议从每行约 28—34 个汉字、20—22 像素字号、1.8—1.95 行距开始试排；手机建议 18—20 像素、1.8—1.95 行距、左右约 20—24 像素留白。以上是待试读调整的起点，不是固定标准。

单段围绕一个意思，保留自然的长短变化。不要为了增加留白把每一句拆成一段，也不要把全部正文装成卡片。连续文字应有安静的底面，互动与图解才适度形成区域。

章标题、正文、补充栏与来源形成清楚层次。只有最值得停留的句子获得放大处理，不把每个粗体句都升级成整屏宣言。

图解紧邻对应的解释：长方形图与尺寸一起出现，叶片图与测量口径一起出现。避免读者在图与解释之间反复跨屏找对应关系。

### 7.2 目录承担选路，章节承担理解

目录保留六篇十八章，可在篇名下加一个具体问题。保留 `#preface` 和 `#ch01` 至 `#ch18`，旧链接仍落在同一章。第四章可换标题，但不更换 ID。

章内目录可以收起；手机默认只露当前章与“目录”文字按钮，不用多个固定浮层挤占正文。点击来源后返回，应尽量停在原来的阅读位置。

结尾只保留三种自然选择：继续下一章、看看相关章、暂停阅读。不要同时出现连续打卡、分享、收藏、评分、徽章等要求。

### 7.3 音乐是一项可选的阅读条件

上传编辑说明称已有轻音乐《窗边》，由读者主动点击后播放。本轮建议保留这条原则，音频来源与许可仍需检查实际资产，不能只凭说明文字完成版权验收。

首次进入默认安静，不通过自动播放营造“进入感”。播放、暂停、音量操作可直接找到；明确提供“安静阅读”。播放失败时保持阅读可用，状态显示“音乐未能播放”，不能假装已经开启。

进入新的章节不突然换曲、不突然变大声。用户开始看有声外部材料时，建议暂停背景音乐，返回后由用户决定是否继续。页面退到后台可暂停；切回前台保持暂停，避免意外发声。

不为按钮增加提示音；章节的关键理解不能依赖听见某段声音。无歌词音乐也可能影响部分读者，应允许完全关闭。不要宣称某首音乐能普遍提升学习效果。

### 7.4 用来源建立可信度，不把阅读变成文献检索

具名研究段落附近保留简短来源入口，展开可看机构、标题、发布时间、核对日期、支持的具体内容与限制。不要只写“来源：网络”。

外部视频不默认嵌入加载，先提供文字摘要与“前往官方资料”入口，不强迫儿童注册。若后续嵌入，须核查年龄要求、追踪与隐私影响，并有等价文字说明。

对示例与真实案例使用明确文字标识：“真实研究”“教学情境”“示例数据”“观点与建议”。它们表示来源性质，不代表权威等级，也不用醒目警告条反复打断阅读。

## 八、内容文件与网站接入约定

### 8.1 保留现有格式，先核对解析器

配套正文继续使用编辑说明中已有的：章节 JSON 注释、`:::lead`、`:::aside`、`:::pause`、`:::details`、`:::interactive`。没有新造十八种内容块。

六种既有互动类型保持为 `prediction`、`context`、`agent`、`counterexample`、`evidence`、`permission`。题干、情境名与反馈在正文母本中维护，前端从母本生成数据，避免写两份长期不一致的文案。

`visual` 注释只记录制作位置与职责。原解析器可能忽略、删除或错误显示 HTML 注释，实际接入时必须检查；在确认前，不应声称仅替换 Markdown 就会自动得到新图解。

**新增呈现与既有互动分开接入。** 如 V11 分层提示没有在正文中使用新 `:::interactive hints` 语法，先通过明确章节和位置挂接，或在取得代码后定义受控的新组件。无法挂接时，正文的三层提示仍可完整阅读。

### 8.2 建议的数据关系

下面是接入建议，不代表现有代码结构。

```json
{
  "schemaVersion": 2,
  "contentVersion": "0.2",
  "chapterId": "ch08",
  "interactiveType": "counterexample",
  "sourceNature": "teaching-simulation",
  "copySource": "book.md",
  "enhancementId": "V08",
  "allowSkip": true,
  "staticEquivalentRequired": true,
  "analyticsContainsUserText": false
}
```

数据需要区分题干、已知条件、读者选择与解释。旧结构把 `### 情境` 后面的一整段当反馈时，可以先继续渲染；实现“先判断”时再迁移结构，不通过脆弱的字面切割长期猜测材料与答案的边界。

新增结构字段须作版本检查，未知类型回退为完整静态文本；不能因某个模块解析失败让整章空白。外部链接和富文本经过安全处理，不把来源文本当脚本或系统指令执行。

### 8.3 同步与发布前的具体工作

先取得真实代码，确认源码与发布目录的关系。若仍使用编辑说明中的 `dist/book.md` 与同步脚本，再沿用该路径；若正文已经迁移，不可同时维护两份互相覆盖的母本。

生成线上正文、离线阅读数据和下载文稿时使用同一内容版本。保留旧章节 ID；章内标题变化后检查目录与定位。旧进度若保存的是像素或百分比，重写后不保证准确，应回退到原章节并提示内容已更新，不伪称能精确恢复原段。

缓存更新只清理本项目拥有的旧缓存。不要清空读者其他网站数据，也不要借改版删除现有阅读偏好。不要把滚动到底直接保存为“理解本章”。

本轮的信件、猜想和敏感情境默认不收集、不联网发送。后续若加入本地笔记，应先说明仅本机保存、共享设备风险与清除方式，提供明确保存按钮；存储失败时提示并保留复制机会。不得静默接入云同步或分析服务。

## 九、验收清单：看懂了什么，比点过什么重要

### 9.1 内容与结构

序章与十八章完整出现，顺序正确，ID 与旧版一致；第四章标题同步更新。正文没有遗留旧称或缺失章节。所有自定义块闭合，未知组件有文本回退。章节中必须默认显示的数据性质和安全边界没有被折叠。

核对长方形全部周长与面积；30 分钟安排的总和；叶片数据的逐项引用；溪桥结论的支持范围。不能把草稿日期、示例地点或演示数字变成实际学校信息。

具名案例链接存在且支持旁边的主张。研究发布时的能力不能未经核对写成当前全面可用；图片、音乐与外部素材的使用条件另作核查。

### 9.2 可操作性与无障碍

使用 320、375、768、1280 CSS 像素宽度检查。正文不出现双向滚动；图表确需局部横向查看时，其说明与等价文字正常换行。200% 字号放大后，按钮、说明和结果无覆盖。

所有操作可用键盘完成，焦点清晰且不被浮层遮住；拖动若存在，必须有单击或键盘替代。目标可点击区域建议至少 44×44 CSS 像素，这是本书采用的更舒适设计目标，不应误写为 WCAG 2.2 所有控件统一的 AA 最小值。

颜色以外还有文字与形状区别。正文对比度按相关 WCAG 要求核验；示例代码不等于正式网站完整达标。屏幕阅读器能获得问题、当前条件、结果与下一步，动态提示不抢读整章。

减少动态时所有学习功能仍可用；关闭脚本与打印时核心文字、计算与解释仍完整。音频默认关闭，错误状态真实。

### 9.3 建议试读方式

先请 3—5 位接近小学毕业至初一阶段的读者作形成性试读。这是小范围寻找卡点，不代表统计验证。不要先把标准答案讲给他们。

| 位置 | 请读者做什么 | 需要观察的证据 |
| --- | --- | --- |
| ch02 | 解释遮挡图为什么只能部分确认 | 分清信息形式与信息完整性 |
| ch04—05 | 把训练、当前材料、保存记录放到对应位置 | 能说清关系，不只背名词 |
| ch06 | 指出清单在何处改变原计划 | 将变化归因于反馈 |
| ch08 | 用另一组尺寸找一个反例 | 能迁移检查，不只记按钮 |
| ch12 | 从示例表选一个有依据的结论 | 不扩大范围、不擅自确定原因 |
| ch13 | 解释旧照片能支持哪一句 | 分清存在与建造年份 |
| ch15 | 判断新增行动是否超出授权 | 说出边界及应该交还给谁 |
| ch17 | 根据一句真实反馈修改作品 | 修改对应读者困难 |

记录读者在哪个词、哪一张图、哪一个操作上停住；先判断是概念不懂、文字不清、界面不明还是材料不足，再修订相应部分。不要一遇到卡顿就增加动画，也不要只问“喜欢吗”。
